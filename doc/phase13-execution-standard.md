## ۲. قرارداد کد — از این توابع استفاده کنید، نسخه‌ی خودتان را ننویسید

```python
from src.config import set_global_seed
from src.data.load_v4 import load_clean_v4, verify_snapshot, status_stability_table
from src.eda_lib.restaurant_taxonomy import (
    add_restaurant_class, classify_restaurants, lifecycle, CORE_CLASS, NON_TARGET_CLASSES,
)

set_global_seed()                    # همیشه اول — بدون استثنا
df = load_clean_v4()                 # ناهار+شام، پاکسازی‌شده، ~۱۵ ثانیه / ۲.۱ گیگابایت
df = add_restaurant_class(df)
core = df[df.restaurant_class == CORE_CLASS]   # تنها سطحی که هدف از آن ساخته می‌شود
```

| نیاز | تابع | نکته |
|---|---|---|
| خواندن خام ستون‌گزین | `load_raw_v4(columns, meals=...)` | فیلتر وعده حین خواندن، نه بعدش |
| خواندن + پاکسازی | `load_clean_v4()` | پیش‌فرض `mealid ∈ {۱,۳}` |
| اثبات یکسانی snapshot | `verify_snapshot()` | معادل assert سلول ۳ نوت‌بوک GPU |
| رده‌بندی موجودیت | `classify_restaurants(names)` | از روی الگوی نام، نه فهرست دستی |
| چرخه‌ی عمر سلف | `lifecycle(df)` | حجم، چگالی، `dead_days` |
| آزمون پایداری هدف | `status_stability_table(df)` | ستون `union` باید پایدار بماند |
| نام‌های هم‌ریشه | `normalization_collisions(df, col)` | ورودی بازسازی نگاشت‌ها |

**اگر تابعی که لازم دارید نیست، آن را در `src/` بنویسید نه در اسکریپت یک‌بارمصرف** —
قاعده‌ی «`notebooks/` روایت، `src/` حقیقت» در این فاز هم برقرار است.

- خروجی‌های حجیم `parquet` باشند نه CSV. `coverage_grid` روی این پنجره ~۱۲ میلیون
  ردیف می‌شود (بند ۱۳-۱۳ ت).
- هر فایل تازه در `data/raw/` باید در `doc/data_manifest.md` با SHA-256 ثبت شود

## ۴. پنج قاعده‌ی سخت این فاز

۱. **هدف فقط از اجتماع سه کد** (`AGENTS.md`، بخش «قاعده‌ی پایداری هدف»). تک‌کد
   `دریافت نشده` روی ۱۴۰۳ تقریباً صفر می‌شود **بدون هیچ خطایی**.
۲. **هدف فقط از رده‌ی `core`.** چهار رده‌ی دیگر (`mokammel`, `guest`, `howzeh`, `test`)
   خارج‌اند — ردیف ۶۶ `decision_log`. مکمل به‌عنوان **فیچر** برمی‌گردد، نه هدف (ردیف ۶۷).
۳. **`Count` را جمع بزنید، ردیف نشمارید.** دیگر باینری نیست (F94).
۴. **قاعده‌ی برش اطلاعاتی بی‌کم‌وکاست** (`AGENTS.md`). بزرگ‌شدن داده هیچ بندی از آن را
   شل نمی‌کند.
۵. **هر run روی داده‌ی تازه:** experiment جدا `phase13_oos` + tag اجباری
   `data_window=v4_extended`. `cv_folds_hash` عوض شده، پس هیچ run این فاز با ~۱۶۹
   پیکربندی فاز ۷ در یک جدول قابل‌مقایسه نیست — این ناسازگاری **درست** رخ می‌دهد ولی
   **بی‌صدا** هم رخ می‌دهد.

  قاعده‌ی «اول دفتر حقایق را ببین» به آن‌ها نمی‌رسید. بند ۵ برای همین است.
