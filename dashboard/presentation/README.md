# داشبورد ارائه

روایت کامل پروژه از مسئله تا ارزش عملیاتی، در ۹ بخش پشت‌سر‌هم — طوری که هم روی
ویدئوپروژکتور ارائه شود و هم به‌تنهایی به‌عنوان گزارش تصویری پروژه خوانده شود.
داشبورد دانش (`../index.html`) مخاطب دیگری دارد: خودِ تیم، حین کار.

```
presentation/
├── index.html   اسکلت و متن روایت (۹ بخش)
├── app.css      توکن‌های طراحی، اجزای مشترک، سبک چاپ
├── app.js       رندر داده، نمودارهای SVG، اسلایدر سیاست
├── data.js      تولید خودکار — دستی ویرایش نشود
└── README.md    همین فایل
```

### قاعده‌ی اصلی: هیچ عددی دستی تایپ نمی‌شود

هر عددی که روی صفحه دیده می‌شود یا مستقیم از یک فایل `reports/` خوانده شده، یا در
`build_presentation.py` از اعداد همان فایل‌ها با یک فرمول صریح مشتق شده است. سه مشتق
اصلی، همگی با اعداد منتشرشده‌ی فاز ۱۰ کنترل شده‌اند:

| کمیت | چطور مشتق می‌شود | کنترل |
|---|---|---|
| پرس و تومان سالانه در هر چندک | `صرفه‌جویی ÷ n_rows × rows_per_year × قیمت پرس` | در τ=۰.۲۰ دقیقاً ۱۶۵٬۱۵۰ پرس / ۶۱.۹ میلیارد، مثل بند ۱۰.۴ |
| هدررفت پایه‌ی سالانه | `صرفه‌جویی ÷ هدررفت‌کاهی` | ۲۳۲٬۳۱۶ پرس ≈ ۸۷.۱ میلیارد |
| کمبود روزانه در هر چندک | `کسر تقاضای برآورده‌نشده × پرس دریافتی در روز` | در τ=۰.۰۲/۰.۱۰/۰.۲۰ همان ۲.۶۵ / ۱۵.۳ / ۳۱.۴ جدول ۱۰.۳ |

اسکریپت اگر حقیقت `F##` یا یافته‌ای که داشبورد به آن ارجاع می‌دهد در دفترها پیدا نشود،
**با خطا متوقف می‌شود** — تا صفحه هرگز عددی بدون شاهد نشان ندهد.

### مبنای واحد

کل صفحه روی **۳۲ هفته‌ی آموزشی، ۳۷۵٬۰۰۰ تومان هر پرس، نقطه‌ی عملیاتی چندک ۰.۲۰** بسته
است (بند ۱۰.۴ و ردیف ۳۴ `doc/decision_log.md`). هیچ بخشی مبنای دیگری نمی‌آورد — عدد
هدررفت ۱۵۷ میلیاردیِ مبنای دوازده‌ماهه‌ی `doc/project-definition.md` عمداً اینجا نیست.

### چند نکته‌ی فنی که تکرارشان آسان است

- **راست‌به‌چپ در SVG خودکار نیست.** محور افقی هر نمودار در `lineChart()` دستی برگردانده
  می‌شود (`X = W - padR - norm × innerW`) و خودِ `<svg>` صریحاً `direction: ltr` است تا
  `text-anchor` قابل‌پیش‌بینی بماند.
- **اندازه‌ی قلم داخل SVG با ویژگی خود عنصر داده می‌شود، نه با CSS.** مقدار CSS بر ویژگی
  غالب است و چون `viewBox` کوچک است، هر مقدار `px` به‌اندازه‌ی ضریب مقیاس بزرگ می‌شود.
- **جهت پرشدن میله‌ها.** میله‌ها با `width` پر می‌شوند و زیر `dir=rtl` از راست شروع
  می‌کنند؛ به همین دلیل نوار اطمینان و نوارهای واگرا با ویژگی‌های *فیزیکی*
  (`right`/`left`) جای‌گذاری می‌شوند تا هم‌راستا بمانند.
- **جهت اسلایدر سیاست.** زیر `dir=rtl` کمینه‌ی `input[type=range]` سمت راست می‌نشیند، و
  سمت راست نمودار هم چندک کوچک است — پس فهرست نسبت‌های هزینه **نزولی** مرتب می‌شود تا
  حرکت دسته و حرکت نشانگر روی منحنی یک جهت داشته باشند.
- **دفتر حقایق یک ستون‌بندی ثابت ندارد** (بعضی بخش‌ها ستون «اندازه اثر» ندارند)، پس
  `table_rows()` ردیف‌ها را با نام سرستون می‌خواند، نه با اندیس.

### چیزی که داشبورد عمداً ندارد

- هیچ کتابخانه‌ی نموداری. همه‌ی نمودارها SVG یا HTML دست‌ساز‌ند تا صفحه آفلاین و سبک بماند.
- هیچ عدد گردشده‌ی بی‌شاهد. جایی که منحنی فقط هفت نقطه‌ی واقعی دارد، درون‌یابی **صریحاً
  اعلام می‌شود**.
- هیچ عدد ترسناک بدون مقیاس‌گذارش. نرخ کمبود همیشه کنار سطح خدمت می‌آید.

### اسلایدر سیاست

دسته روی **نسبت هزینه‌ی کمبود به مازاد** است، نه روی خودِ چندک — چون نسبت هزینه چیزی است
که مدیریت سلف می‌فهمد و چندک نیست. تبدیل با همان تصحیح ردیف ۳۶ `decision_log` انجام
می‌شود:

$$\tau^{*}_{\rho} = \frac{C_o}{C_u + C_o} = \frac{1}{1 + C_u/C_o}$$

نُه ایستگاه اسلایدر طوری انتخاب شده‌اند که **هر هفت چندکِ واقعاً اندازه‌گیری‌شده‌ی منحنی**
قابل‌دسترس باشند؛ دو ایستگاه باقی‌مانده درون‌یابی‌شده‌اند و خودِ صفحه این را می‌گوید.

## به‌روزرسانی

بعد از هر تغییری در `reports/` یا `doc/`:

```bash
python dashboard/build_presentation.py
```

## اجرای محلی

باز کردن مستقیم فایل کافی است. اگر مرورگر برای `file://` سخت‌گیری کرد:

```bash
python -m http.server 8777 && echo "http://127.0.0.1:8777/dashboard/presentation/"
```
